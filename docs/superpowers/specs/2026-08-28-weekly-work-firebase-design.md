# 주간업무추진사항 Firebase 웹사이트 설계

## 목표

Google Sheet와 Apps Script로 운영하던 주간업무 수합을 Firebase 기반 웹사이트로 이전한다. 일반 사용자는 공용 비밀번호로 접속해 모든 주차와 부서를 열람·수정하고, 관리자는 별도 이메일·비밀번호 계정으로 설정·계정·변경 이력을 관리한다. 기존 Google Sheet는 한 번 이전한 뒤 보관용으로 유지한다.

## 확정된 운영 규칙

- 일반 사용자는 사이트 공용 비밀번호를 입력한다.
- 접속한 일반 사용자는 모든 주차와 모든 부서 내용을 수정할 수 있다.
- 과거 주차도 일반 사용자가 계속 수정할 수 있다.
- 관리자는 Firebase 이메일·비밀번호 계정을 사용하며 교체·추가·비활성화할 수 있다.
- 매주 월요일 00:05(Asia/Seoul)에 다음 주 월요일 주차를 자동 생성한다.
- 관리자는 임의 날짜 주차를 수동으로 생성할 수 있다.
- 웹사이트 UI는 루트 `DESIGN.md`의 Steep 편집형 디자인 시스템을 따른다.
- A4 출력물은 현재 Google Sheet 결과물의 순서·문구·색상·표·줄바꿈을 재현한다.
- 첫 화면은 분할형이다. 데스크톱은 날짜·부서 탐색과 주간표·편집을 동시에 제공하고, 모바일은 선택 메뉴와 탭으로 재배치한다.

## 기술 구조

- 프런트엔드: React, TypeScript, Vite
- 호스팅: Firebase Hosting
- 데이터베이스: Cloud Firestore Native, `asia-northeast3`
- 인증: Firebase Authentication
  - 일반 사용자: 공용 비밀번호 검증 후 제한된 기여자 토큰 발급
  - 관리자: 이메일·비밀번호 로그인과 관리자 역할 클레임
- 서버 작업: Cloud Functions for Firebase
  - 공용 비밀번호 검증
  - 관리자 전용 작업
  - 매주 자동 주차 생성
  - 부서 내용 변경 이력 생성
- 보호: 닫힌 Firestore Rules, Firebase App Check, 서버 비밀값은 Secret Manager에 저장

정적 화면은 CDN에서 먼저 제공한다. 선택한 한 주의 문서만 Firestore에서 구독해 초기 로딩과 실시간 갱신 비용을 제한한다. A4 인쇄 화면은 별도 경로와 스타일 청크로 분리한다.

## 데이터 모델

### `settings/site`

- `serviceName`: 서비스명
- `defaultMeetingTitle`: 새 주차에 사용할 회의 종류
- `timeZone`: `Asia/Seoul`
- `autoCreateNextWeek`: 자동 생성 여부
- `updatedAt`: 마지막 설정 변경 시각

### `departments/{departmentId}`

- `name`: 표시 이름
- `order`: 표시 순서
- `active`: 새 주차 포함 여부
- `omitWhenEmpty`: 비어 있을 때 출력에서 생략할지 여부

### `weeks/{YYYY-MM-DD}`

- `date`: 기준일
- `dateLabel`: 한국어 출력용 날짜
- `meetingTitle`: 생성 당시 회의명 스냅샷
- `departmentSnapshot`: 생성 당시 부서 ID·이름·순서
- `createdBy`: `scheduler`, `admin`, `migration` 중 하나
- `createdAt`: 생성 시각

### `weeks/{weekId}/entries/{departmentId}`

- `htmlContent`: 편집기 HTML
- `blocks`: 텍스트·표 구조
- `plainText`: 검색과 폴백용 텍스트
- `version`: 낙관적 동시성 버전
- `updatedAt`: 수정 시각
- `updatedByRole`: `contributor`, `admin`, `migration` 중 하나

### `weeks/{weekId}/entries/{departmentId}/revisions/{version}`

- 변경 직전 항목 전체 스냅샷
- 변경 시각과 변경 역할
- 관리자가 현재본으로 복원할 수 있는 버전 번호

### `adminProfiles/{uid}`

- 관리자 표시 이름, 이메일, 활성 상태
- 실제 비밀번호는 Firebase Authentication이 관리

## 저장과 충돌 처리

편집 화면은 입력에 즉시 반응하고 저장 상태를 별도로 표시한다. 저장 시 사용자가 열어둔 `version`과 서버 최신 버전을 비교한다. 같으면 트랜잭션으로 저장하고 버전을 증가시킨다. 다르면 자동 덮어쓰기하지 않고 최신본과 내 편집본을 보존한 채 `최신본 불러오기` 또는 `내 내용으로 다시 저장`을 선택하게 한다.

업데이트 전 내용은 Firestore 트리거가 버전 문서로 기록한다. 복원도 새 변경으로 취급해 복원 직전 현재본을 다시 이력에 남긴다.

## 화면 구조

### 접속 잠금

- 서비스명과 공용 비밀번호 입력
- 잘못된 비밀번호, 요청 제한, 네트워크 오류를 구분해 안내
- 성공 시 기여자 세션을 유지하고 작업 화면으로 이동

### 분할형 작업 화면

- 고정 영역: 서비스명, 관리자 진입, A4 인쇄
- 왼쪽 탐색: 주차 목록, 부서 목록, 마지막 수정 시각
- 오른쪽 본문: `주간표`와 `편집` 탭
- 데스크톱은 본문만 스크롤하고 탐색은 고정한다.
- 768px 이하에서는 탐색을 상단 선택 메뉴로 바꾸고 본문 탭만 스크롤한다.

### 편집기

- 기존 기능인 굵게, 기울임, 밑줄, 글머리표, 번호 목록, 링크, 표 삽입을 지원한다.
- 외부 문서 표 붙여넣기와 한글 워드프로세서 HTML 정리를 지원한다.
- 자동 저장은 하지 않는다. 사용자가 저장을 명시하고 저장 중·완료·충돌 상태를 확인한다.

### 관리자 화면

- 회의명과 부서 순서 관리
- 임의 날짜 주차 생성
- 공용 비밀번호 변경과 기존 기여자 세션 무효화
- 관리자 계정 추가·비활성화
- 부서별 변경 이력 확인·복원

### A4 출력

- `@page { size: A4; }`와 인쇄 전용 CSS를 사용한다.
- 제목, 회의 종류, 날짜, 부서 라벨, 본문, 표를 현재 시트 형식으로 배치한다.
- 브라우저 인쇄 대화상자에서 PDF로 저장한다.
- 기존 주간 시트와 대표 주차를 화면·PDF로 대조해 줄바꿈과 페이지 수를 조정한다.

## 성능 원칙

- 정적 자산은 Firebase Hosting CDN으로 제공한다.
- 첫 화면에서 선택한 주차의 항목만 구독한다.
- 주차별 부서는 개별 문서로 저장해 한 부서 수정이 전체 문서를 다시 전송하지 않게 한다.
- 인쇄 화면과 관리자 화면은 지연 로딩한다.
- 원격 폰트보다 빠른 시스템 폴백을 우선하고, 필요한 폰트만 서브셋·preload한다.
- 모든 목록은 안정적인 ID 키를 사용하고 React 불필요 재렌더링을 측정한다.

## 오류 처리

- 접속 오류: 비밀번호 불일치, 요청 제한, 네트워크 실패를 구분한다.
- 저장 오류: 편집 내용을 브라우저 상태에 유지하고 재시도할 수 있게 한다.
- 동시 수정: 자동 병합이나 자동 덮어쓰기를 하지 않는다.
- 자동 주차 생성: 같은 날짜 문서가 있으면 성공한 무작업으로 종료한다.
- 마이그레이션: 한 행이 실패해도 전체를 숨기지 않고 실패 행을 별도 보고서에 남긴다.

## 기존 데이터 이전

Google Sheet의 숨김 `제출원본`에서 `기준시트`, `기준일자`, `부서`, `내용HTML`, `내용구조JSON`, `내용텍스트`, `최종수정시각`을 읽는다. 날짜별 주차와 부서 항목을 만들고 최초 버전을 `migration`으로 표시한다. 대표 주차의 웹 출력과 기존 시트를 대조한 뒤 Firebase를 원본으로 전환한다.
