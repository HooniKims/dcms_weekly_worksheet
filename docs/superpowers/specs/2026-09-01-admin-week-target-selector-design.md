# 관리자 주차 삭제 대상 선택 설계

## 목적

관리자가 바깥 편집 화면을 나갔다가 날짜를 바꾸지 않아도 관리자 창 안에서 휴지통으로 이동할 활성 주차를 직접 고를 수 있게 한다. 화면에 표시된 날짜, 확인창의 날짜, 실제 저장소로 전달되는 주차 ID는 항상 같은 대상을 가리켜야 한다.

## 사용자 경험

- `주차 관리` 영역에 활성 주차 전체를 최신순으로 보여주는 날짜 선택 목록을 둔다.
- 목록의 초기값은 관리자 창을 열 때 바깥 편집 화면에서 선택되어 있던 주차다.
- 목록 위에 `현재 삭제 대상: 2026년 9월 7일` 형식으로 현재 대상을 명확히 표시한다.
- 실행 버튼에도 `2026년 9월 7일을 휴지통으로 이동`처럼 선택한 날짜를 포함한다.
- 목록에서 날짜를 바꾸면 안내 문장과 실행 버튼 문구가 즉시 같은 날짜로 갱신된다.
- 관리자 창 안의 삭제 대상 선택은 바깥 편집 화면의 주차 선택과 부서 편집 문맥을 변경하지 않는다.
- 선택한 주차를 휴지통으로 옮긴 뒤에는 남은 활성 주차 중 최신 주차가 다음 삭제 대상으로 선택된다.
- 마지막 활성 주차는 휴지통으로 이동할 수 없으며 기존 안내와 비활성 상태를 유지한다.

## 구성 요소와 상태

`Workspace`는 `AdminDialog`에 활성 주차 배열을 전달한다. `AdminDialog`는 이를 `AdminWeekTrash`에 전달하고, `AdminWeekTrash`가 관리자 창 전용 `archiveTargetWeekId` 상태를 소유한다.

`AdminWeekTrash`는 다음 값을 같은 선택 상태에서 계산한다.

- 선택 목록의 현재 값
- `현재 삭제 대상` 안내의 날짜 레이블
- 실행 버튼의 날짜 레이블
- 확인 대화상자의 날짜 레이블
- `onArchiveWeek`에 전달할 주차 ID

바깥 편집 화면의 `selectedWeekId`는 초기값으로만 사용한다. 관리자 창 내부에서 목록을 바꾸어도 `Workspace`의 선택 주차 변경 콜백은 호출하지 않는다.

## 데이터 흐름

1. 관리자 창이 열리면 현재 편집 주차 ID로 삭제 대상을 초기화한다.
2. 관리자가 목록에서 다른 날짜를 고르면 로컬 삭제 대상만 바뀐다.
3. 관리자가 날짜가 포함된 휴지통 버튼을 누르면 같은 날짜가 포함된 확인창을 표시한다.
4. 확인하면 해당 주차 ID를 기존 `onArchiveWeek` 흐름에 전달한다.
5. 저장소 응답으로 활성 주차 배열이 갱신되면 삭제된 ID가 사라졌는지 확인하고, 사라졌다면 최신 활성 주차를 새 대상으로 선택한다.

## 오류와 동시 실행

- 보관 요청 중에는 날짜 선택 목록, 보관 버튼, 모든 복원 버튼을 함께 비활성화한다.
- 보관 실패 시 기존 대상 선택을 유지하고 현재 오류 메시지를 표시한다.
- 활성 주차가 하나뿐이면 선택 목록은 보이되 보관 버튼은 비활성화하고 마지막 주차 안내를 표시한다.
- 선택 대상이 외부 갱신으로 사라졌을 때는 남은 최신 활성 주차를 자동 선택한다.

## 반응형·접근성

- 날짜 선택은 기존 입력 필드와 동일한 Paperlogy, hairline, 16px radius 토큰을 사용한다.
- 레이블과 `select`를 연결하고 현재 삭제 대상 안내는 텍스트로도 제공한다.
- 모바일에서는 안내, 선택 목록, 실행 버튼을 세로로 쌓고 가로 넘침 없이 전체 너비를 사용한다.
- 한국어 날짜와 조사 사이가 부자연스럽게 분리되지 않도록 의미 단위 줄바꿈을 유지한다.

## 검증

- 현재 편집 주차가 초기 삭제 대상으로 표시되는 컴포넌트 테스트
- 관리자 창 안에서 다른 주차를 고르면 안내·버튼·확인창·콜백이 모두 같은 주차를 사용하는 테스트
- 보관 성공 뒤 남은 최신 주차로 대상이 이동하는 테스트
- 보관 실패 및 요청 중 비활성 상태 테스트
- 마지막 활성 주차 보호 테스트
- 1280px, 768px, 375px 브라우저 화면에서 선택 목록과 날짜 문구의 잘림·겹침·한글 줄바꿈 확인

## 범위 제외

- 관리자 창에서 바깥 편집 화면의 주차를 변경하는 기능
- 주차 영구 삭제
- 여러 주차를 한 번에 선택하거나 일괄 보관하는 기능
