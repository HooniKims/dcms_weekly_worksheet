# 사이트 폰트·주차 탐색·비밀번호 분리 설계

## 목표

기존 Google Sheets 인쇄 양식은 그대로 유지하면서 웹사이트 사용 화면을 Paperlogy로
통일한다. 사용자는 접속 직후 최신 입력 주차를 확인하고, 한 개의 날짜 선택기를 통해
다른 주차로 이동해 부서별 저장 내용을 조회·수정할 수 있어야 한다. 일반 사용자와
관리자는 서로 다른 비밀번호로 인증한다.

## 범위

1. 웹사이트 UI에 Paperlogy를 적용한다. 주간업무추진사항 보고서와 인쇄 CSS의
   `Malgun Gothic` 계약은 변경하지 않는다.
2. `말씀 및 기도` 부서는 내용이 없을 때 보고서 화면과 인쇄물에서 행을 렌더링하지
   않는다. 부서 선택 목록에는 항상 남겨 새 내용을 입력할 수 있게 한다.
3. 사이드바의 전체 주차 버튼 목록을 한 개의 `입력 날짜` 선택기로 교체한다. 최신 주차를
   기본값으로 선택하고, 선택값에는 연·월·일·요일을 모두 표시한다.
4. 날짜를 바꾸면 해당 주차의 부서별 엔트리를 불러오고, 현재 선택한 부서의 편집 내용을
   갱신한다. 부서 목록의 저장 완료 표시는 선택한 날짜의 데이터만 반영한다.
5. 일반 접속 비밀번호와 관리자 비밀번호를 분리한다. 관리자 화면은 이메일 입력을 없애고
   비밀번호만 받는다.

## 화면 구조

### 날짜 선택

- 데스크톱: 기존 사이드바 상단에 `입력 날짜` 레이블과 네이티브 `select`를 배치한다.
- 모바일: 기존 모바일 주차 선택기도 같은 옵션·표기·동작을 공유한다.
- 선택값 표기: `2026년 8월 31일 (월)`.
- 최신 생성 주차가 초기 선택값이다. 자동 생성 주차와 관리자 생성 주차에는 옵션 보조
  문구로 `입력 주차`, 마이그레이션 데이터에는 `이전 자료`를 붙인다.
- 긴 버튼 목록은 렌더링하지 않는다. 옵션 목록은 사용자가 선택기를 열 때만 보인다.

### 날짜별 부서 내용

- 날짜 변경은 기존 repository의 `load(weekId)` 경계를 사용한다.
- 변경 중에는 기존 화면을 유지하고, 로드가 끝나면 `entries`와 편집 초안을 함께 교체한다.
- 현재 부서가 새 주차의 부서 스냅샷에도 존재하면 선택을 유지한다. 존재하지 않으면 첫 번째
  활성 부서로 이동한다.
- 보고서/편집 탭 선택은 날짜 변경 시 유지한다.

### 관리자 인증

- 관리자 버튼을 누르면 `관리자 비밀번호` 입력 하나만 표시한다.
- 인증 성공 뒤에만 새 주차 생성 폼을 표시한다.
- 잘못된 비밀번호 메시지는 `관리자 비밀번호가 맞지 않습니다.`로 통일한다.

## 폰트

- Paperlogy 공식 저장소의 Regular(400), Medium(500), Bold(700) WOFF2 파일을
  `public/fonts`에 자체 호스팅한다.
- 웹사이트 기본 UI 토큰 `--font-sohne`을 Paperlogy 우선 스택으로 변경한다.
- 제목용 serif 토큰은 기존 잠금 화면 등에서 계속 사용할 수 있지만, 사이트 작업 화면의
  일반 글꼴은 Paperlogy를 상속한다.
- `.report-form`은 기존 `--report-font`를 유지해 화면 미리보기와 인쇄물 모두 Google Sheets
  양식을 보존한다.
- `font-display: swap`을 사용해 초기 화면을 막지 않는다.

## 인증과 환경변수

### 로컬 개발

- 루트 `.env`:
  - `VITE_LOCAL_SITE_PASSWORD=<site-password>`
  - `VITE_LOCAL_ADMIN_PASSWORD=<admin-password>`
- `.env.example`에는 같은 변수명과 개발 기본값을 문서화한다.
- 이 값은 로컬 데모 repository에서만 사용한다. `VITE_` 값은 브라우저에 포함되므로 배포
  보안 경계로 사용하지 않는다.

### Firebase 배포

- Firebase Functions Secret:
  - `SITE_PASSWORD`
  - `ADMIN_PASSWORD`
- 기존 `unlockWithSharedPassword`는 `SITE_PASSWORD`를 검증하고 contributor custom token을
  반환한다.
- 새 `unlockAdminWithPassword` callable은 `ADMIN_PASSWORD`를 검증하고 `admin: true`,
  `role: "admin"` claim을 가진 custom token을 반환한다.
- 두 callable 모두 App Check를 적용한다.
- 웹 클라이언트는 관리자 custom token으로 로그인한 뒤 기존 `createWeek` callable을 호출한다.
  `createWeek`의 admin claim 검증은 유지한다.
- 비밀번호 원문은 Firestore와 클라이언트 번들에 저장하지 않는다.

## 모델과 인터페이스 변경

- `WorkspaceRepository.signInAdmin(email, password)`를
  `WorkspaceRepository.signInAdmin(password)`로 변경한다.
- `AdminDialog`의 이메일 상태·입력·demo 기본값을 제거한다.
- 일반/관리자 로컬 비밀번호는 `import.meta.env` 선언을 통해 타입을 부여한다.
- 주차 옵션 표시 문자열은 `domain/week.ts`의 순수 함수로 만들어 단위 테스트한다.

## 빈 말씀 및 기도 처리

- 보고서 렌더러는 `department.omitWhenEmpty` 또는 부서명이 `말씀 및 기도`인 경우,
  `plainText.trim()`이 빈 엔트리를 생략한다.
- 기존 마이그레이션 스냅샷에 `omitWhenEmpty: false`가 저장돼 있어도 동일하게 동작해야 한다.
- 다른 부서의 빈 내용은 기존 Google Sheets 규칙대로 `* 없음`을 표시한다.

## 테스트

### 자동 테스트

- `ReportView`: 빈 `말씀 및 기도` 행은 없고 다른 빈 부서는 `* 없음`을 표시한다.
- 주차 표시 함수: 연도와 요일, `입력 주차`/`이전 자료` 보조 문구를 만든다.
- `WorkspaceNavigation`: 긴 주차 버튼 대신 선택기 한 개를 렌더링하고 변경 콜백을 호출한다.
- `AdminDialog`: 이메일 입력이 없고 비밀번호 하나로 인증한다.
- `localRepository`: `.env` 기반 일반/관리자 비밀번호를 각각 검증한다.
- Functions: 관리자 비밀번호 callable의 입력 검증과 claim 생성 경계를 확인한다.

### 실제 브라우저 검증

1. `<site-password>`로 일반 접속한다.
2. 최신 주차와 연도가 날짜 선택기에 보이는지 확인한다.
3. 이전 주차를 선택해 부서 체크 표시와 편집 내용이 해당 날짜 데이터로 바뀌는지 확인한다.
4. 내용이 없는 `말씀 및 기도`가 보고서와 A4 인쇄 미리보기에서 사라지는지 확인한다.
5. 관리자 창에서 `<admin-password>`만 입력해 주차 생성 폼까지 진입하는지 확인한다.
6. 화면 UI는 Paperlogy, 보고서 계산 스타일은 Malgun Gothic인지 확인한다.
7. 기존 표·굵게·밑줄이 포함된 주차를 A4로 출력해 레이아웃 회귀가 없는지 확인한다.

## 오류 처리와 보안

- 일반/관리자 비밀번호 오류는 역할에 맞는 메시지로 표시하고 입력값은 유지한다.
- 날짜 로드 실패 시 현재 화면과 초안을 보존하고 저장 실패와 구분되는 오류 메시지를 표시한다.
- Secret 미설정은 배포/함수 시작 단계에서 드러나게 하며 클라이언트 기본값으로 우회하지
  않는다.
- 네 자리 비밀번호는 강한 보안 수단이 아니라 학교 내부 접근 경계다. App Check와 Firebase
  Security Rules의 인증 요구를 유지한다.

## 제외 범위

- 관리자별 계정, 비밀번호 변경 UI, 비밀번호 재설정 흐름은 이번 작업에 포함하지 않는다.
- Google Sheets 인쇄 양식의 글꼴·열 너비·색상·A4 페이지 규격은 변경하지 않는다.
- 부서 구조나 기존 Firestore 자료의 마이그레이션은 변경하지 않는다.
