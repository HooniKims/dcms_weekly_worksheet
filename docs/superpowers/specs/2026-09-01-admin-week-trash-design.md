# 관리자 주차 휴지통 설계

작성일: 2026-09-01

## 목표

관리자가 잘못 만들었거나 당분간 사용하지 않을 주차를 안전하게 숨기고 나중에 복원할 수 있게 한다. 휴지통으로 이동한 주차의 입력 내용과 수정 이력은 삭제하지 않으며, 일반 사용자의 날짜 목록·검색·저장 대상에서는 즉시 제외한다.

## 선택한 방식

주차 문서를 다른 컬렉션으로 옮기거나 삭제하지 않고 휴지통 상태를 기록한다. Firebase에서는 기존 `weeks/{weekId}` 문서에 보관 시각을 저장하고, 로컬 개발 저장소에서는 별도의 휴지통 주차 ID 목록을 저장한다. 기존 데이터에 휴지통 상태가 없으면 활성 주차로 해석한다.

이 방식은 하위 `entries`와 `revisions`를 이동하지 않으므로 내용 손실 위험이 가장 낮고 복원도 빠르다.

## 관리자 화면

- 관리자 인증 후 `주차 관리` 영역을 표시한다.
- 현재 선택한 주차와 `이 주차를 휴지통으로 이동` 버튼을 제공한다.
- 버튼을 누르면 날짜를 포함한 확인창에서 입력 내용이 보존되고 일반 목록과 검색에서 숨겨진다는 점을 알린다.
- 마지막 활성 주차는 휴지통으로 이동할 수 없으며 버튼과 서버 양쪽에서 차단한다.
- 휴지통에 주차가 있으면 날짜 목록과 각 주차의 `복원` 버튼을 표시한다.
- 휴지통 이동 또는 복원 중에는 동일 작업 버튼을 비활성화하고, 완료·실패 결과를 기존 관리자 상태 메시지에 알린다.

## 저장소 계약

`WorkspaceSnapshot`은 활성 `weeks`와 관리자용 `archivedWeeks`를 구분해 제공한다. `WorkspaceRepository`는 다음 두 작업을 추가한다.

- `archiveWeek(weekId)`: 선택 주차를 휴지통으로 이동하고 갱신된 워크스페이스를 반환한다.
- `restoreWeek(weekId)`: 휴지통 주차를 활성화하고 갱신된 워크스페이스를 반환한다.

두 작업은 관리자 인증이 필요하다. 휴지통 작업 뒤 선택 주차가 사라졌다면 남은 활성 주차 중 가장 최신 주차를 선택하고 첫 번째 활성 부서를 연다. 복원은 현재 선택을 바꾸지 않는다.

## Firebase와 검색

- 주차의 휴지통 상태는 서버 시각으로 기록한다.
- 휴지통 이동 API는 관리자 권한, 주차 존재 여부, 활성 주차가 두 개 이상인지 확인한다.
- 휴지통 이동 후 해당 주차의 검색 색인 문서를 제거한다.
- 복원 API는 휴지통 상태를 해제하고 해당 주차의 검색 색인을 다시 만든다.
- 전체 검색 색인 재생성도 휴지통 주차를 제외한다.
- 개별 입력 저장과 검색 색인 갱신은 휴지통 주차를 거부하거나 색인을 제거한다.
- Firestore 직접 저장 규칙도 상위 주차가 휴지통이 아닐 때만 입력 생성을 허용한다.

검색 색인 갱신이 실패하면 주차 상태는 성공으로 보고하지 않는다. 서버 응답은 휴지통 상태와 검색 노출 상태가 함께 정리된 뒤에만 성공한다.

## 로컬 개발 저장소

정적 이전 자료는 수정할 수 없으므로 `archivedWeekIds`에 휴지통 주차 ID를 저장한다. 활성 목록과 검색은 이 ID를 제외하며, 휴지통 목록은 동일한 정적·로컬 주차 데이터에서 구성한다. 복원하면 ID만 제거하므로 입력 내용이 그대로 돌아온다.

## 동시성과 오류 처리

- 휴지통 이동 중 사용자가 다른 주차를 선택하면 늦게 도착한 응답이 현재 선택을 덮어쓰지 않는다.
- 이미 휴지통에 있는 주차를 다시 이동하거나 활성 주차를 다시 복원하는 요청은 현재 상태를 반환하는 멱등 작업으로 처리한다.
- 휴지통 주차를 오래 열어둔 브라우저의 저장 요청은 서버에서 거부한다.
- 존재하지 않는 주차, 마지막 활성 주차, 권한 부족은 구분된 오류로 처리하고 사용자에게 안전한 한글 안내를 표시한다.

## 접근성 및 시각 규칙

- 휴지통 이동은 기존 위험 버튼 스타일과 휴지통 아이콘을 재사용한다.
- 복원은 기존 보조 버튼 스타일과 복원 아이콘을 사용한다.
- 버튼 이름에는 대상 날짜를 포함해 보조 기술에서도 작업 대상을 알 수 있게 한다.
- 모바일에서 주차 관리와 휴지통 목록이 가로 스크롤을 만들지 않게 기존 관리자 카드 폭과 줄바꿈 규칙을 따른다.

## 검증

- 활성 주차를 휴지통으로 이동하면 날짜 목록과 검색 결과에서 제외되는 저장소 테스트
- 입력 내용과 수정 이력이 삭제되지 않는 Firebase 실행 계획 테스트
- 마지막 활성 주차 차단과 멱등 처리 테스트
- 복원 후 날짜 목록과 검색 결과가 다시 생성되는 테스트
- 휴지통 주차 저장 거부와 Firestore 규칙 테스트
- 현재 선택 주차 이동 후 다음 최신 주차로 전환되는 컨트롤러 테스트
- 관리자 확인창, 성공·실패 메시지, 바쁜 상태, 복원 버튼 테스트
- 일반 사용자는 휴지통 관리 기능을 볼 수 없는 회귀 테스트
- 375px, 768px, 1280px 관리자 도구와 휴지통 상태의 실제 브라우저 시각 검증

## 범위 밖

- 여러 주차 일괄 이동 또는 일괄 복원
- 일반 사용자의 휴지통 열람
